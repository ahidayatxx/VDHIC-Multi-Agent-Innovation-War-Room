# Agent Spec: VDHIC Multi-Agent Innovation War Room (`vdhic-warroom-agent`)

## Overview
The VDHIC Multi-Agent Innovation War Room (`vdhic-warroom-agent`) is an AI-powered advisory panel that reviews, critiques, and scores digital health innovations in Indonesia against the **Value-Based Digital Health Innovation Canvas (VDHIC v1.25)** framework. It orchestrates 4 specialized sub-agents to analyze a proposal from regulatory, interoperability, clinical, and health economic perspectives, returning a unified executive review report and block-by-block score card.

---

## Architecture & Sub-Agents

```
                             +-------------------------------+
                             |    VDHIC Coordinator Agent    |
                             |      (vdhic_coordinator)      |
                             +---------------+---------------+
                                             |
         +-------------------+---------------+-------------------+-------------------+
         |                   |                                   |                   |
+--------v-------+  +--------v-------+                  +--------v-------+  +--------v-------+
| Regulatory &   |  | Interop & Tech |                  | Clinical &     |  | Economics &    |
| Data Governance|  | Specialist     |                  | Evidence Lead  |  | Scale Lead     |
| (Block 10, 12) |  | (Block 6, 13)  |                  | (Block 1,7,11) |  | (Block 8,9)    |
+----------------+  +----------------+                  +----------------+  +----------------+
```

1. **Coordinator Agent (`vdhic_coordinator`)**:
   - Primary interface receiving digital health project descriptions or canvas JSON drafts.
   - Routes analysis to specialists, collects evaluations, and synthesizes the final VDHIC v1.25 Review Report.

2. **Regulatory & Compliance Specialist (`regulatory_specialist`)**:
   - **Focus**: Governance Spine (Block 10: Medical Device / SaMD Risk Classes I–III, ISO 13485/IEC 62304, Kemenkes Regulatory Sandbox) & Data Governance (Block 12: UU PDP No. 27/2022, data localization, patient consent).

3. **Interoperability & Tech Architect (`interop_specialist`)**:
   - **Focus**: Design Phase (Block 6: SATUSEHAT FHIR R4 API integration, SIMRS / PCare connectivity, ICD-10/LOINC/SNOMED CT/KFA terminologies) & Tech Governance (Block 13: Cybersecurity, ISO 27001, API gateways, DR/BC, SLAs).

4. **Clinical & Evidence Specialist (`clinical_specialist`)**:
   - **Focus**: Discover Phase (Block 1: Health Challenge) & Deliver Phase (Block 7: Evidence Plan - Feasibility Pilot → RCT → RWE) & Clinical Governance (Block 11) & Quintuple Aim (Population Health, Patient Experience, Provider Satisfaction).

5. **Health Economics & Scale Specialist (`economics_specialist`)**:
   - **Focus**: Deliver Phase (Block 8: Scale Strategy, Block 9: Business Model - BPJS INA-CBGs tariff inclusion, Kapitasi incentives, unit economics) & Quintuple Aim (Cost Reduction, Health Equity).

## Example Use Cases

### Scenario 1: Tele-Cardiology AI Screening Solution
- **Input**: A proposal for an AI-powered ECG mobile app deployed at Puskesmas in West Java.
- **Output**: 
  - VDHIC Maturity Assessment: `◐ Validated` (Pilot stage).
  - SaMD Risk Classification: `Class IIa` (requires ISO 13485 + Kemenkes Regulatory Sandbox registration).
  - Interoperability Requirements: Must map ECG waveform & diagnostic summaries to SATUSEHAT `Observation` and `DiagnosticReport` FHIR R4 profiles.
  - Economics: Guidance on BPJS Kapitasi incentive alignment for primary care prevention.

---

## Tools Required

1. **`kemenkes_regulatory_lookup`**: Search regulatory sandbox guidelines, BPOM SaMD risk class criteria, and UU PDP data protection requirements.
2. **`satusehat_fhir_lookup`**: Retrieve SATUSEHAT FHIR R4 profile specifications and mandatory coding dictionaries (ICD-10, LOINC, SNOMED CT, KFA).
3. **`bpjs_reimbursement_lookup`**: Look up BPJS Kesehatan INA-CBGs tariff inclusion standards and Puskesmas Kapitasi incentive frameworks.

---

## Constraints & Safety Rules

1. **Indonesian Regulatory Alignment**: All compliance guidance must strictly reflect Indonesian legal and health authority frameworks (UU PDP No. 27/2022, Kemenkes Regulatory Sandbox, SATUSEHAT Playbook).
2. **No Clinical Diagnosis**: The agent provides digital health strategy and regulatory guidance only; it must explicitly disclaim providing direct clinical medical treatment or diagnostic decisions.
3. **Authoritative Citations**: Never fabricate regulatory standards or FHIR endpoint URLs.

---

## Success Criteria (Eval Metrics)

1. **Canvas Block Coverage (100%)**: Evaluation report must address all 13 Canvas Blocks and all 5 Quintuple Aim dimensions.
2. **Regulatory Accuracy (>= 90%)**: Correctly identifies SaMD risk tier and SATUSEHAT FHIR profile requirements across evaluation test benchmarks.
3. **Actionability Score (>= 4.5/5)**: Provides concrete, step-by-step roadmaps for sandbox application, pilot site onboarding, and FHIR integration.
